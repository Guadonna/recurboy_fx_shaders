# Четвёртая ручка: интенсивность displacement

В штатном `conjur::setSpeed()` положение ручки преобразуется в скорость времени `-2 + 4 × value`. Само значение в `shaderParams[3]` не записывается. Поэтому объявление `uniform u_x3` в новом шейдере само по себе не подключает ручку.

## Что добавляет патч

`fx-fourth-knob.patch` предназначен для **ofxVideoArtTools** ревизии `00dc93725073b1cf5bfc5d4a56e8d3256a995d81` и делает три вещи:

- Записывает ограниченное положение четвёртой ручки в `shaderParams[3]`, откуда существующий код передаёт `u_x3`.
- Передаёт `u_fx_knob3_available=1`, чтобы шейдер отличал новое подключение от штатного хоста.
- Передаёт координаты `u_fx_drift`, рассчитанные на CPU по абсолютному времени. Центр медленно ходит по обеим осям от 6% до 94% кадра; приблизительные периоды — 90 и 68 секунд. Скорость этого движения не зависит от интенсивности эффекта.

Прежнее управление скоростью времени сохраняется для остальных эффектов. В reaction diffusion после патча: **0 — displacement выключен, 1 — максимум**. Сам рост при нуле продолжает работать. На половине четвёртой ручки штатное масштабированное время останавливается, но новый центр продолжает двигаться по независимым часам.

## Установка

Это изменение исходников хоста, поэтому копирования `.frag` недостаточно. Нужна пересборка RecurBoy на совместимом образе с исходниками и зависимостями openFrameworks. Перед заменой исполняемого файла сохраните его резервную копию.

Из каталога addon выполните, подставив реальные пути:

```sh
cd /path/to/openFrameworks/addons/ofxVideoArtTools
git apply --check /path/to/fx-fourth-knob.patch
git apply /path/to/fx-fourth-knob.patch
```

Затем пересоберите свой проект RecurBoy штатной командой (для проекта с openFrameworks Makefile — `make -j1` из каталога проекта), установите полученный исполняемый файл способом, принятым в вашей прошивке, и перезапустите RecurBoy. Патч совместим с приложенным `feedback-pingpong.patch`: оба проверены совместно. Если ваша прошивка отличается от указанной ревизии и `git apply --check` не проходит, не применяйте патч принудительно.

В облаке применён патч к оригинальному upstream и скомпилирован его `conjur.cpp` с тестовой заменой зависимостей openFrameworks. Проверены передача положения ручки, сохранение старого управления временем и независимое движение центра. **Это модульная проверка C++, не сборка ARM/прошивки и не проверка физической ручки.**

## Если хост ещё не обновлён

Шейдер работает с автоматическим displacement интенсивностью 30%. Четвёртая ручка по-прежнему меняет скорость и направление его времени; в среднем положении движение центра останавливается. Прямое управление интенсивностью появится только после установки патча и пересборки.

После обновления выберите reaction diffusion, сбросьте Wet в ноль на несколько кадров, верните Wet в 1 и начните с четвёртой ручки около 0.3–0.5. Сравните крайние положения: при 0 фронты продолжают распространяться без вихревого переноса, при 1 деформация заметно усиливается.
