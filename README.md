# RecurBoy Recursive Transformations — 10 FX

[Каталог](https://github.com/Guadonna/recurboy_fx_shaders/tree/main) · `collections/recursive` · v0.2.0

Вложенные преобразования видео, зеркальные залы и рекурсивные следы.

Feedback-варианты выполняют одну итерацию в кадр; глубина накапливается во времени. Log Droste и Tile Inception используют аналитическое повторение координат вместо неограниченного числа проходов.

## Установка и ручки

В отдельном ZIP шейдеры находятся в `Fx/`; в All Collections — непосредственно в `recursive/`, только `.frag`. Документация есть в отдельных ZIP и ветках. Обновление: замените одноимённые файлы. Префиксы шейдеров уникальны для типа эффектов.

На странице EFFECT: ручка 0 — Wet/сброс, 1 и 2 — из таблицы, 3 — штатная скорость и направление часов. Около середины четвёртой ручки модуляция останавливается, видео и память продолжают обновляться. Патч передачи ручки не нужен. Старт: **100% / 55% / 75% / 65%** (у первых пяти Datamosh можно поднять третью ручку до 90%). После смены эффекта подержите Wet=0 несколько кадров.

| Файл | Механизм | Ручка 1 | Ручка 2 | Чтений |
|---|---|---|---|---:|
| `rcs01_zoom_tunnel.frag` | Кадры уходят внутрь масштабируемого тоннеля. | Масштаб шага | Глубина памяти | 2 |
| `rcs02_rotating_echo.frag` | Поворот и масштаб предыдущего кадра создают вложенную спираль. | Поворот шага | Память и масштаб | 2 |
| `rcs03_log_droste.frag` | Видео повторяется на логарифмических уровнях масштаба. | Плотность вложений | Спиральный сдвиг | 2 |
| `rcs04_mirror_hall.frag` | Память отражается по двум осям, образуя расходящийся зеркальный зал. | Сдвиг зеркал | Удержание | 3 |
| `rcs05_tile_inception.frag` | Каждая плитка содержит уменьшенное видео и собственную копию памяти. | Количество плиток | Вложенность | 3 |
| `rcs06_corner_echoes.frag` | Копии памяти стягиваются к углу кадра. | Угол / смещение | Глубина | 2 |
| `rcs07_opposing_tunnels.frag` | Две половины изображения рекурсивно движутся в противоположных масштабах. | Раскрытие тоннелей | Память | 2 |
| `rcs08_strip_inception.frag` | Каждая горизонтальная полоса содержит уменьшенную версию памяти. | Количество полос | Глубина | 2 |
| `rcs09_orbit_frames.frag` | Рамка памяти вращается и смещается вокруг текущего кадра. | Шаг поворота | Плотность вложений | 2 |
| `rcs10_foldback_memory.frag` | Рекурсивная память выворачивается по V-образному сгибу. | Положение сгиба | Память | 2 |

Цвет берётся из источника. RGB-разделение и цветовая интерференция намеренно могут окрашивать ЧБ; остальные варианты проверяются на сохранение ЧБ с чистой памятью. Feedback сохраняет прежние цвета до сброса Wet.

## Производительность и проверки

GLES 2.0 / GLSL ES 1.00, один проход. Новые эффекты используют не более 4 чтений текстур; прежние — до 6. Pixel Sorting целиком ограничен 4 чтениями. **FPS и температура на Raspberry Pi не измерены**, облачные проверки не подтверждают устранение аппаратного зависания. [Проверка на устройстве](docs/performance.md).

Шейдеры с памятью требуют завершённого предыдущего RGB8 framebuffer. Исследованный upstream может читать и писать один буфер, что не определено GLES; отдельный прежний `docs/feedback-pingpong.patch` исправляет это для addon `00dc93725073b1cf5bfc5d4a56e8d3256a995d81`. Если хост уже чередует буферы, патч не нужен. На ARM он здесь не собран. Лицензия addon включена рядом. Pixel Sorting использует только текущее видео.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
EGL_PLATFORM=surfaceless .venv/bin/python tools/validate_collection.py
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/package.py
```
