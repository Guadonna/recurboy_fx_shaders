# RecurBoy Organic FX — 11 эффектов

**v0.2.0: широкие диапазоны, сильные деформации и рост в цветах вашего видео.** Однопроходные FX для [cyberboy666/recurBOY](https://github.com/cyberboy666/recurBOY), GLES 2.0 / GLSL ES 1.00. По-прежнему 3–7 чтений текстуры, без дополнительных буферов со стороны шейдеров. Версия предварительная: 25 FPS и температура на Raspberry Pi ещё не измерены.

## Установка и обновление

1. Распакуйте релизный ZIP. Замените одноимённые `.frag` в `~/Fx/` на Pi либо в папке `Fx` в корне USB-накопителя. Не копируйте ZIP целиком в меню FX. Для работы шейдеров Python и сборка не нужны.
2. В RecurBoy перейдите вправо в FX, выберите эффект и нажмите SELECT. Кнопка FX включает обработку. Регулируйте эффект на странице EFFECT: на странице PATTERN ручки относятся к исходному генератору.
3. При переключении/обновлении эффекта подержите **ручку 0 в нуле несколько кадров**, затем поднимайте. Это выводит исходное видео и перезаписывает feedback им. Для полностью чёрного старта используйте чёрный источник при Wet=0.
4. Отправная точка: **ручки 0/1/2 = `1.0 / 0.55 / 0.70`**. Крайние значения теперь намеренно дают крупные разрывы, длинные следы и контрастные маски. Старые положения ручек звучат визуально иначе.

## Ручки

Ручка 0 — Wet (0…100%). Она одновременно меняет подмешивание источника в память; уменьшение Wet влияет и на развитие узора. Низкие значения дают исходное изображение с эффектом, максимум — полный эффект.

Ручки 1 и 2 — из таблицы ниже. У большинства размеров/деформаций квадратичная кривая: первая половина удобна для точной настройки, вторая быстро разгоняет эффект. Ручка 3 — штатная скорость времени RecurBoy, например 0.65. Она управляет временной деформацией liquid/temporal/elastic; feedback обновляется каждый кадр, даже при остановленном времени.

Пиксельные расстояния относятся к фактическому FX framebuffer. Длина магнитных штрихов и амплитуда мембраны дополнительно зависят от поля/видео; значения таблицы не означают число дополнительных выборок. Положение ручек не добавляет проходов или циклов.

Быстрые положения для ручек **0 / 1 / 2** (вводятся вручную):

- **Контуры:** `0.85 / 0.25 / 0.50` — мелкие детали с читаемым исходником.
- **Живой поток:** `1.00 / 0.55 / 0.70` — основное положение новой версии.
- **Срыв:** `1.00 / 0.85 / 0.95` — крупная геометрия, длинная память, сильный контраст. Для возврата на секунду опустите Wet в ноль.

## Цвет и рост

У **mycelium / reaction diffusion / differential growth** больше нет встроенной зелёной или розовой палитры. Интенсивность рисунка хранится в максимальном канале RGB, а соотношения R:G:B берутся из текущего пикселя входного видео. Поэтому:

- ЧБ-вход даёт ЧБ-узор; даже цвет предыдущего feedback не просачивается после переключения на ЧБ.
- Цветной вход сохраняет свои оттенки и насыщенность в узоре; яркость меняет симуляция. Это не обещание совпадения исходных RGB-значений по яркости.
- При смене палитры узор перекрашивается по текущему кадру. Полностью чёрные участки не содержат оттенка, поэтому проходящий по ним фронт нейтральный.

В RGB8 framebuffer невозможно независимо хранить два химических поля и произвольный видимый RGB-цвет в одном пикселе. Поэтому в v0.2.0 growth/reaction используют **одно поле интенсивности с пространственным возбуждением и торможением**, без скрытой упаковки битов и дополнительных проходов. Reaction diffusion теперь является стилизацией с локальной активацией и дальним торможением, **а не прежней двухкомпонентной Gray–Scott**. Differential growth остаётся растровой имитацией роста; геометрическая сетка и новые вершины не создаются.

У остальных эффектов цвет может оставаться в старых следах после смены источника — это их обычная память. Чистый запуск на ЧБ проверен для всех 11 эффектов.

## Производительность и совместимость

Базовая цель — Pi Zero / Zero W и Zero 2 W, SD-вывод и штатный лимит 30 FPS. Число выборок не увеличено относительно v0.1.0; цветовая арифметика — `mediump`, координаты точнее при доступном `highp`. Нет ray marching, циклов, шумовых октав или float-текстур. Некоторые формулы стали сложнее: равное число выборок не гарантирует равную скорость.

**25 FPS и температура требуют замера на устройстве.** Шейдеры не измеряют температуру, не меняют частоты и не могут гарантировать отсутствие перегрева. [Проверка производительности и необязательный термомонитор](docs/performance.md) включены в архив. Уменьшение размера видео без изменения FX framebuffer не снижает стоимость рендера.

В исследованном upstream feedback читает framebuffer, в который одновременно пишет. Для переносимого результата нужны два чередующихся буфера; приложен прежний патч к addon, проверенный только на применимость. [Совместимость и точные ревизии](docs/compatibility.md). Патч автоматически не устанавливается и на Pi нами не собран.

Temporal refraction использует одну рекурсивную память, без массива независимых прошлых кадров. Elastic membrane, кристаллизация, эрозия и акварель — художественные модели для ограниченного GPU.

## Проверки и примеры

Из корня исходного репозитория, на Linux с EGL/Mesa:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
EGL_PLATFORM=surfaceless .venv/bin/python tools/validate.py --frames 360
EGL_PLATFORM=surfaceless .venv/bin/python tools/validate_color_controls.py
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/package.py
```

Первая проверка компилирует/линкует GLSL ES 1.00 и рендерит все эффекты с раздельными RGB8 буферами. Вторая проверяет ЧБ, соответствие оттенков входу, смену палитры, независимость роста от выбора цветового канала и заметное изменение обоих параметров. Это реальные результаты рендера Mesa, не замеры Pi. [Общий отчёт](docs/cloud-validation.json), [цвет и диапазоны](docs/color-controls.json).
