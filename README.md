# RecurBoy Organic FX — 11 эффектов

Лёгкие однопроходные FX для [cyberboy666/recurBOY](https://github.com/cyberboy666/recurBOY): GLES 2.0 / GLSL ES 1.00, исходное видео + RGB feedback, три ручки параметров и штатная ручка времени. Компиляция, реальный рендер и накопление feedback проверены в Mesa. **Версия 0.1.0 — предварительный релиз: 25 FPS и температура на Raspberry Pi ещё не измерены.**

## Установка

1. Распакуйте релизный ZIP. Скопируйте содержимое `Fx/` в `~/Fx/` на Pi либо папку `Fx` в корень USB-накопителя. Внутри находятся только 11 самостоятельных `.frag`; сборка и Python для их работы не нужны.
2. В RecurBoy перейдите вправо в FX, выберите эффект и нажмите SELECT. Кнопка FX включает обработку. Для регулировки FX используйте страницу EFFECT; в странице PATTERN ручки относятся к исходному генератору.
3. Ручка 0 — Wet: 0 даёт исходное видео и перезаписывает feedback им. Подержите её в нуле несколько кадров при переключении эффектов, затем поднимайте. Для реакционных эффектов начните с 1.0; уменьшение Wet меняет и симуляцию.
4. Ручки 1 и 2 — параметры из таблицы. Отправная точка: `1.0 / 0.35 / 0.4`. Ручка 3 — штатная скорость времени RecurBoy, например 0.65. Она изменяет временную деформацию у liquid/temporal/elastic; feedback у всех эффектов обновляется каждый кадр, даже когда время остановлено.

## Эффекты

Число чтений — верхний бюджет на пиксель при Wet > 0. Все эффекты работают в один проход. Изменение ручек не добавляет циклов или выборок.

| Файл | Эффект | Ручка 1 | Ручка 2 | Чтений |
|---|---|---|---|---:|
| `01_liquid_memory.frag` | Вязкие стекающие следы | Размер потока | Память | 4 |
| `02_mycelium.frag` | Ветвящиеся нити от границ видео | Шаг ветвления | Питание | 7 |
| `03_erosion.frag` | Перенос цвета по яркостному рельефу | Размыв | Осаждение | 5 |
| `04_reaction_diffusion.frag` | Два вещества, модель Gray–Scott | Feed | Kill | 6 |
| `05_temporal_refraction.frag` | Преломление накопленной памяти | Искажение | Память | 3 |
| `06_magnetic_ink.frag` | Вытягивание цвета по касательным к границам | Направление | Длина штрихов | 5 |
| `07_crystallization.frag` | Мозаичные грани с удержанием изображения | Размер граней | Удержание | 3 |
| `08_elastic_membrane.frag` | Колеблющаяся деформация с инерционным следом | Упругость | Затухание | 5 |
| `09_digital_fossils.frag` | Квантованные, смещённые слои памяти | Смещение | Память | 3 |
| `10_capillary_watercolor.frag` | Диффузия цвета и тёмные края | Растекание | Пигмент | 6 |
| `11_differential_growth.frag` | Растущие возбуждаемые контуры с торможением | Шаг роста | Реакция / торможение | 7 |

Это художественные модели для ограниченного GPU. Differential growth здесь реализован через поле активации и торможения, без динамической сетки и добавления вершин. Temporal refraction использует одну рекурсивную память; независимых кадров истории нет. Elastic membrane — деформация изображения, без отдельного поля скорости. Кристаллизация, эрозия и акварель — стилизации, а не физические симуляторы. Модели reaction/differential хранят состояние прямо в R/G и используют ограниченную палитру; альфа для хранения не подходит, поскольку штатный framebuffer — RGB.

## Производительность и нагрев

Базовая цель — обычный **Pi Zero / Zero W**, также поддерживаемый upstream Zero 2 W. Использованы 3–7 выборок, `mediump` для цвета, точные координаты при доступном `highp`, без ray marching, циклов, шумовых октав, float-текстур и дополнительных проходов. Это ограничивает стоимость, но не устанавливает минимальный FPS.

Начинайте с SD-вывода, штатного ограничения 30 FPS, простого источника видео и одного FX. Разрешение framebuffer зависит от вывода RecurBoy: уменьшение размера видео само по себе не уменьшает стоимость FX. Не начинайте проверку с 720p/1080p; не разгоняйте Pi ради этих эффектов. Для оценки суммарной нагрузки проверяйте также ваш самый тяжёлый исходный генератор или видеоклип.

**Шейдер не читает температуру и FPS и не может обещать защиту от перегрева.** Методика проверки всех 11 эффектов и необязательный процессный термоконтроль — в [docs/performance.md](docs/performance.md). До аппаратных замеров требование «всегда не менее 25 FPS» остаётся неподтверждённым.

## Совместимость feedback

В проверенном upstream есть чтение из framebuffer, в который одновременно ведётся запись. Стандарт GLES не гарантирует результат такой схемы. Весь набор использует штатные имена uniform, но надёжная рекурсия требует двух чередующихся буферов. Включён небольшой патч к `ofxVideoArtTools`; он проверен на применимость, но не собран на Pi. Подробности и точные ревизии: [docs/compatibility.md](docs/compatibility.md). Не заменяйте прошивку вслепую; сравните вашу версию.

## Разработка и проверки

На Linux с EGL/Mesa:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
EGL_PLATFORM=surfaceless .venv/bin/python tools/validate.py
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/package.py
```

`validate.py` компилирует и линкует все программы как GLSL ES 1.00, рендерит с раздельными RGB8 буферами, проверяет сухой сигнал, крайние параметры, отрицательное/долгое время, живое изменение feedback и несколько разрешений. В `artifacts/` записываются PNG и JSON; это иллюстрации на синтетическом входе, не снимки устройства. Если PyOpenGL не находит GL/EGL, установите системные Mesa EGL/GL библиотеки. На оригинальном Pi образе используется другой графический стек: облачный runner не является тестом прошивки.

`tools/package.py` создаёт воспроизводимый ZIP в `dist/`, с 11 файлами, инструкциями, термомонитором и SHA-256. GitHub Actions запускает проверки; тег `v0.1.0` публикует prerelease с ZIP и контрольной суммой.
